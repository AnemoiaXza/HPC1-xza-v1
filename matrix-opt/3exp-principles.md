# 三个 MPI 实验的原理详解

## 一、矩阵乘法 (gemm)

### 1.1 算法原理

矩阵乘法 C = A × B，其中 A 为 m×n，B 为 n×k，结果 C 为 m×k。核心计算：

$$C[i][j] = \sum_{p=0}^{n-1} A[i][p] \times B[p][j]$$

时间复杂度 O(m × n × k)，当矩阵为方阵时是 O(n³)。

### 1.2 并行划分策略

代码采用 **二维棋盘划分 (2D Block Decomposition)**：

- 将 worldSize 个进程排列成 `rowBlock × colBlock` 的网格
- 矩阵 A 按行切分为 rowBlock 块，B 按列切分为 colBlock 块
- 进程 (rowB, colB) 负责 A 的 rowB 块 × B 的 colB 块，得到 C 的对应子块

```
     B (n×k)
  ┌──────────┐
  │ b0  b1   │  ← colBlock=2
  │          │
  └──────────┘

A (m×n)      C (m×k)
┌─────┐     ┌──────────┐
│ a0  │     │ c00  c01 │
├─────┤  =  ├──────────┤
│ a1  │     │ c10  c11 │
└─────┘     └──────────┘
rowBlock=2
```

### 1.3 通信模式

| 阶段 | 操作 | 通信原语 |
|------|------|---------|
| 数据分发 | Rank 0 将 A 的子块发给各进程 | `MPI_Isend`（非阻塞） |
| 分发 B | Rank 0 将 B（转置后）的子块发出 | `MPI_Isend` |
| 接收 | Worker 接收自己的 A、B 子块 | `MPI_Recv` |
| 同步 | 等待所有分发完成 | `MPI_Barrier` |
| 结果回收 | Worker 将局部结果发回 Rank 0 | `MPI_Send` / `MPI_Recv` |
| 汇总 | Rank 0 将各子块拼成完整 C | 本地内存操作 |

### 1.4 关键优化

- **B 矩阵转置**：计算前将 B 转置，内层循环访问右矩阵时变为连续读取，大幅提升缓存命中率
- **非阻塞发送**：`MPI_Isend` 让 Rank 0 的分发操作可以流水线化
- **OpenMP 混合**：每个 MPI 进程内部用 `#pragma omp parallel for` 做局部计算

### 1.5 进程数限制

代码限制进程数须为平方数（1/4/9/16...），超出部分被丢弃：
```cpp
worldsize = rowBlock * colBlock;  // 只使用行列之积
```

## 二、卷积操作 (conv)

### 2.1 算法原理

二维卷积在输入图像上滑动一个 kernel，计算每个窗口的加权和：

$$Output[i][j] = \sum_{r=0}^{K-1}\sum_{c=0}^{K-1} Input[i+r][j+c] \times Kernel[r][c]$$

输出尺寸 = (InputSize - KernelSize) / Stride + 1。

### 2.2 两种实现

代码实现了两种卷积算法：

**Naive 卷积（直接滑窗）**：
```
对于每个输出位置 (i, j)：
  取输入中以 (i, j) 为起点的 K×K 窗口
  与 Kernel 逐元素相乘并累加
```
时间复杂度：O(H_out × W_out × K²)，对每个输出做 K² 次乘法。

**img2col 卷积（图像展开为矩阵）**：
```
1. 将每个 K×K 的感受野展开成一维列向量（长度 K²）
2. 将所有列向量拼成矩阵 flattenImg（尺寸：H_out·W_out × K²）
3. 将 Kernel 也展平为一维向量（长度 K²）
4. 卷积 = flattenImg × Kernel，退化为矩阵-向量乘法
5. 使用 cblas_sgemm（OpenBLAS）高效完成
```

**关键优势**：img2col 将卷积转化为 BLAS 的 GEMM 操作，享受 OpenBLAS 的 SIMD 优化。对于大 kernel 和大输入，img2col 的重排开销一次性支付后，矩阵乘法远快于 naive 循环。

### 2.3 并行划分策略

- **按行划分**：将输入图像沿行方向切分给各进程
- 每个进程处理 `total_xsteps / worldSize` 个行
- 进程 i 获得行范围 `[i × rows_per_proc × xStep, (i+1) × rows_per_proc × xStep + xKernel - xStep)`
- 相邻进程间有 xKernel - xStep 行的重叠（halo 区域），保证边界处卷积正确

```
Input Image:
┌──────────────┐
│  proc 0      │
│  (含 halo)   │
├──────────────┤  ← 重叠 xKernel-xStep 行
│  proc 1      │
│  (含 halo)   │
├──────────────┤
│  proc 2      │
└──────────────┘
```

### 2.4 通信模式

| 阶段 | 内容 |
|------|------|
| 分发 | Rank 0 用 `MPI_Isend` 将各行块（含重叠）发给 worker |
| 计算 | 各进程独立做 naive/img2col 卷积 |
| 回收 | Worker `MPI_Send` 结果；Rank 0 `MPI_Recv` 收集 |

## 三、池化操作 (pooling)

### 3.1 算法原理

池化在输入特征图上滑动 kernel 窗口，对每个窗口内的元素做聚合运算（最大池化或平均池化）。代码实现的是 **最大池化 (Max Pooling)**：

$$Output[i][j] = \max_{r=0}^{K-1}\max_{c=0}^{K-1} Input[i·K + r][j·K + c]$$

Kernel 大小 = Stride = 4（无重叠池化），输出尺寸 = 输入尺寸 / 4。

### 3.2 与卷积的本质区别

| 特性 | 卷积 | 池化 |
|------|------|------|
| 运算 | 乘加（加权和） | 比较（取最大值） |
| 计算量 | O(n² × K²) | O(n² × K²)（但每个元素仅是 max 比较） |
| 算术强度 | 高（K² 次乘加） | 低（K² 次比较，无乘法） |
| 通信/计算比 | 低 | **高** — 这是关键问题 |

**池化的通信/计算比远高于卷积**：每个输出元素仅需比较操作（<1 个时钟周期），而数据传输仍要完整搬运整个子矩阵。这导致池化在 MPI 分布式场景下几乎必然减速。

### 3.3 并行划分策略

- 与卷积类似的按行划分
- 但无 halo：stride = kernel size，窗口不重叠
- 各进程处理不重叠的行块，边界恰好对齐

### 3.4 通信模式

与卷积相同：Rank 0 分发 → 独立计算 → Rank 0 回收。

## 四、三种实验的对比总结

### 4.1 计算/通信比

| 实验 | 计算量 | 通信量 | 计算/通信比 | 单机并行效果 |
|------|--------|--------|------------|-------------|
| Gemm | O(n³) | O(n²) | O(n) → 随规模增大 | 大矩阵可加速 |
| Conv (img2col) | O(n²·K²) | O(n²) | O(K²) → 恒定 | 中等 |
| Conv (naive) | O(n²·K²) | O(n²) | O(K²) | 中等 |
| Pooling | O(n²·K²) | O(n²) | O(K²) → 但每 FLOP 极轻 | **最差** |

### 4.2 单机 MPI 适用性排序

1. **Gemm（最适用）**：计算 O(n³) 远大于通信 O(n²)，大数据集下并行收益可盖过通信开销
2. **Conv img2col（中等）**：转化为矩阵乘法后计算效率高，但通信量不变
3. **Conv naive（差）**：循环开销大，通信/计算比高
4. **Pooling（最差）**：计算太轻量（仅比较操作），通信开销绝对主导，多进程必慢

### 4.3 关键启示

- **MPI 多进程的收益取决于计算/通信比**。计算越密集、通信越少，加速效果越好
- **单机场景优先用 OpenMP 多线程**，消除通信开销
- **跨节点时**，只有计算量足够大的任务才值得用 MPI 分发
- **img2col 技巧**将卷积转化为矩阵乘法是利用现有高性能库的通用策略，在深度学习框架（Caffe、早期 TensorFlow）中广泛使用
